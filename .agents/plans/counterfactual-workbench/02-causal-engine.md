# Forked causal experiment engine

Prerequisite: integration ownership is established. This package must pass deterministic and model-equivalence tests before UI wiring.

## New modules and existing dependencies
New `src/lib/counterfactual/{types,targets,engine,evidence}.ts` under existing `src/lib/`. Separate target selection, numerical stepping and serialization. Use existing arena `createWorld`, `stepWorld`, `observeAgent`, `decodeAction`, `createSnapshot`; connectome `stepModel`, `aggregateOutputs`, state/scratch factories; `NEURAL_SUBSTEPS_PER_TICK`; graph parsing/derived disconnected graph; replay config identity. Do not import Node-only training scripts into browser code.

New `scripts/experiments/counterfactual.ts` under existing `scripts/experiments/` consumes the same engine from Node/tsx and verifies exported runs. Add an npm script. New tests under `tests/unit/` compare the engine to existing `scripts/training/episode.ts#runEpisode` with explicit production K and authored left/parked right. Tests may import that script; runtime browser modules may not.

## Request and target contract
Version this model `arena-counterfactual-v1`. Strictly validate before allocations: base seed unsigned 32-bit; seed count 4–16; warmup 0–300 ticks; horizon 30–300 ticks; topology biological/rewired/disconnected; target from a closed set. Default 8 seeds, warmup 120, horizon 180. Use consecutive seeds with unsigned wraparound; record their exact list. No hidden training or held-out claim; these are paired evaluation seeds.

Derive groups from graph indices: eight individual input-channel assignments (food bearing/distance, hazard bearing/distance, forward/left/right clearance, speed), bridge neurons (neither input nor output), and descending output neurons. Name targets as model mappings, not anatomy. Record sorted graph indices and exact biological body IDs as decimal strings. Show counts before execution; reject empty targets. Cross-check compatible input/output dimensions and zero within the allowed rate range. The graph remains immutable, and all branches use identical topology and decoder.

## Fork and intervention
For each seed, initialize world and neural rates at zero. During warmup, observe the left agent, run K neural substeps, aggregate/decode authored action, and step both agents with right action `[0,0,0]`. At warmup end, retain the full world including RNG, contact bookkeeping and score state and a copy of the full rate vector.

Create baseline, sham (empty mask) and lesion branches from detached copies of that exact checkpoint. Each has separate state/scratch/output buffers. Baseline and sham take the identical numerical route with empty targets. For lesion, zero targeted rates at the fork **before** the first recurrent scatter, then after every `stepModel` call and before aggregate/decode. Persist across all horizon ticks. Do not modify weights, observations, scores or world rules.

Post-fork reward is final left score minus fork left score, component-wise for score, pickups, contacts and distance. Store per-seed baseline/sham/lesion results and lesion-minus-baseline differences. Summary is mean paired difference and a labeled descriptive normal interval `mean ± 1.96 * sampleSD / sqrt(n)`; no significance or biological causal inference. Include sham differences, which must be exactly zero or the experiment fails validation.

Capture deterministic sampled snapshots from fork (offset zero) through final tick, at most 61 frames per branch/seed. Define a new counterfactual replay frame containing `createSnapshot(world, 1)` plus detached per-agent score components captured from that same world tick; the existing ArenaSnapshot has no scores and cannot supply them retrospectively. Frames include both agents, food and hazards, and each agent's cumulative score, pickups, contacts and distance. Store the fork's score components alongside frames; display the left agent's post-fork increments by subtracting those fixed fork values, including zero at offset zero. Never derive score from sampled positions or reuse the final score at earlier ticks. Each branch renders its own environment; do not overlay branch-specific food/hazards as though shared. Replay timestamps must be identical for baseline/sham/lesion. Zero horizon is invalid. Cancellation discards incomplete runs; publish no partial summary as completed.

## Evidence and deterministic regeneration
Export a distinct schema with model/schema version, exact request and seeds, graph SHA-256 of the actual binary used, topology/source artifact identity, world config/fingerprint, K, authored decoder and parked-opponent convention, sorted target indices/body IDs, per-seed checkpoint summary and outcomes, sampled replay, statistics, provenance labels. Keep timing metadata and runtime provenance separate from deterministic result fields. Runtime provenance records Node version/platform/architecture in Node, or browser user-agent and engine-visible information in browsers; browser architecture may be unknown and is never guessed. No credentials, server settings or synthetic weights. Do not reinterpret the existing arena replay schema or the DGX export schema.

CLI verifies version, bounded options, expected seeds/targets/K/config and current artifact digests before running. Default `--verify` recomputes deterministic evidence and fails nonzero on any mismatch. Same-runtime repeatability and the locally tested browser/Node path must pass exact verification. Optional `--compare-numerical` is explicitly a diagnostic numerical comparison, not exact evidence verification: identities, key sets, dimensions, ticks, seeds, body IDs, contacts and pickup counts must match exactly. Only schema-declared continuous fields may differ by absolute <=1e-6 OR relative <=1e-6, with at most eight leaves differing above both absolute and relative 1e-13 noise floors, following the conservative fixture policy in `tests/fixtures/cross-arch-tolerance.ts`. Report comparison mode, maximum error and number of inexact leaves. Diagnostic comparison exits zero only for an exact or within-budget numerical match, labels the latter `numerically close; not exact reproduction`, and exits nonzero for any structural/discrete or over-budget mismatch. Unknown producer runtime is labeled unknown and grants no larger tolerance. The fixture policy is a conservative rejection threshold, not evidence that 600-tick trajectories reproduce on every architecture; do not broaden it without measured evidence. Never automatically retry failed exact verification with tolerance. Cross-architecture contact divergences are reported as non-reproduction, not normalized away. Bound input file size (16 MiB). Reject NaN/nonfinite output before serialization. Document commands to generate and verify a real-graph example; preserve its settings/hash and outcome in validation docs, not large incidental exports.

## Tests and gates
- Fork does not alias rate/world/nested contact/RNG data; independent steps cannot mutate checkpoint or another branch.
- Baseline/sham exactly agree in outcomes and every frame for real and fixture graphs.
- Unperturbed baseline equals `runEpisode` for total warmup+horizon on at least three seeds; post-fork subtraction independently checked. A product oracle-binding/runner test verifies the same tick order for a matched zero-action opponent.
- Handcrafted graph proves a positive intervention effect on neural output, with nonzero target state at fork and recurrent propagation; every substep mask applies. Empty sham never modifies rates. Disconnected mode uses the existing graph transform.
- Independent paired-statistic calculation; negative/zero effects valid; frame endpoints and cap; bound validation and seed wraparound. Compare intermediate frame scores against independently stepped world states and include them in exact/diagnostic evidence verification.
- CPU repeatability and Node/browser evidence agreement at deterministic fields. Across CPU architectures, report the existing floating-point caveat and exercise the explicit diagnostic comparison contract rather than promise bit identity. Test allowed tiny continuous noise, excessive numeric error/dense divergence, and exact-field tampering; default verification rejects all altered deterministic evidence.
- Tampered graph identity, target membership, seeds, version, replay or outcomes are rejected by CLI verification. No raw dataset or GPU dependency for these tests.
