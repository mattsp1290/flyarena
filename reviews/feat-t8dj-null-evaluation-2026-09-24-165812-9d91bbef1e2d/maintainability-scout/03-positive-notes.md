# Positive Notes

- **Determinism comes from the canonical task order, not completion order.** `runShardedEvaluation` (`scripts/null/null-evaluate.ts:256-316`) collects results into a `Map` keyed by `graphId`. `assembleRaw` (`:367-401`) then rebuilds the output by iterating the seed-sorted `index.seeds`. That is the right structure: shard count and scheduling cannot leak into the bytes, and the `--shards 1` vs `--shards 3` CLI test (`tests/unit/null-evaluate.test.ts:158-184`) exercises the real `fork` path end to end rather than a mock.
- **Pull-based work queue.** The shared `nextTaskIndex` and the `assignNext`-on-result pattern (`:276-289`) mean a slow biological/disconnected task never leaves other shards idle. `workerCount = Math.max(1, Math.min(shardCount, tasks.length))` (`:309`) handles `--shards` larger than the task count without forking idle children.
- **Layered integrity checks, each with a clear purpose.** `verifyRewiredFiles` (`:108-131`) checks gzip size and sha256 for *every* file before forking, and reports *all* mismatches at once (not just the first). `loadVerifiedGraphBinary` (`null-worker.ts:70-80`) then re-checks the decompressed bytes that are actually passed to `parseGraphBinary`. The doc comments explain why both exist.
- **The disconnected control reuses the browser's own seam.** `graphFromTask` (`null-worker.ts:96-101`) goes through `buildGraphBufferForMode`, so the headless disconnected control matches what the product renders instead of re-deriving it. It verifies the biological source sha before deriving.
- **Statistics reuse, not reimplementation.** `graphStats` (`null-stats.ts:29-34`) delegates to `conditionStats(values, resamples, conditionRng(bootstrapSeed, label))`, and the paired comparison uses `pairedStats` with its own label, `'paired|biological-vs-rewired-seed0'` (`null-report.ts:241-246`). Every CI is therefore a pure function of (seed, label, data), and adding or removing rewired graphs cannot shift another graph's CI. `quantileIndex` (`null-stats.ts:56-57`) explicitly follows `bootstrapCI`'s floor/ceil-minus-one convention, so the two quantile definitions don't quietly diverge.
- **Degenerate-case handling in the pure stats.** `buildHistogram` handles a zero span and `value === max` explicitly (`:140-146`). `nullSummary` and `rankStatistics` throw on empty input with clear messages. The tests hand-compute the expected indices in comments (`null-stats.test.ts:46-51`), which makes the quantile convention reviewable.
- **Report prose is carefully hedged.** `renderReportMarkdown`'s Limitations section and the degenerate-null callout (`null-report.ts:301-306, 369-378`) avoid significance or causal language, as the plan's non-goals require.
- **Consistent CLI plumbing.** Both new CLIs use the shared `requireValue`/`requirePositiveInt`/`requireNonNegativeInt` from `scripts/training/cli.ts`, the `Unknown argument: ${flag}` convention, and the `main()` try/catch → `console.error` → `process.exit(1)` shape used in `scripts/training/evaluate.ts`. That avoids the drifted local `requireValue` copy in `scripts/experiments/seed-sweep.ts:96`.
